# Check-in Calculator

Find out exactly when online check-in opens for your flight, in the airport's time zone
and in yours, and add that moment to your calendar.

Live site: https://rusewww.github.io/check-in_calculator/

## What it does

1. Pick the departure airport by IATA code (or airport / city name).
2. Enter the scheduled departure date and time, as printed on your ticket (local time
   at the airport).
3. Choose how long before departure check-in opens: **Hours** (12, 24, 36, 48, 72) or
   **Days** (3, 5, 7, 10, 30, 60), or type a custom number.
4. Optionally pick the time zone to show times in (defaults to the airport's zone).

You get the opening time in the airport's zone and in yours, the UTC offset of each, the
time-zone difference at that moment, a live countdown or "check-in is open" status, and
buttons to **add the opening time to Google Calendar** or **download an .ics file** for
Apple Calendar, Outlook and others. The link in the address bar always reflects the
current inputs, so it can be shared.

The top bar has an Auto / Light / Dark theme switch and a language button (English by
default, Ukrainian and German). The visual design follows the approved Claude Design
mockups: Geist type, warm neutrals, a violet accent, and the result presented as a
boarding pass with a large opening time.

Daylight-saving changes are handled: "N hours before" is exact elapsed time, "N days
before" is the same local time N calendar days earlier at the airport, and a departure
time that does not exist or exists twice on a change-over night is flagged.

Everything is computed in the browser from its built-in IANA time-zone database. There
is no server, no account, no analytics, and no data leaves the device.

## Development

Requires Node.js 22 or newer.

```bash
npm install
npm run dev          # local dev server
npm test             # unit tests (Vitest)
npm run lint         # ESLint
npm run typecheck    # JSDoc types checked with tsc
npm run format       # Prettier
npm run build        # production build into dist/
npm run data:build   # regenerate public/data/airports.json from open data
npm run check        # everything CI runs
```

Layout:

```
src/core/      pure logic (time zones, period rules, calculation, search, URL state, calendar)
src/data/      loads the airport dataset
src/ui/        DOM components, state, strings, styles
src/web/       website entry point
scripts/       data pipeline
public/data/   generated airport dataset (committed)
tests/         Vitest suites, including checks on the shipped dataset
docs/          architecture and decisions
```

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the design, the data sources and
the reasoning behind the technical choices.

## Airport data

`public/data/airports.json` is generated by `scripts/build-airports.mjs` from:

- [OurAirports](https://ourairports.com/data/) (public domain): codes, names, region,
  country, type, scheduled-service flag, coordinates.
- [mwgg/Airports](https://github.com/mwgg/Airports) (MIT): IANA time zone per airport.
- [geo-tz](https://github.com/evansiroky/node-geo-tz) (MIT, build time only): time zone
  from coordinates for airports missing above.

The dataset is validated by the test suite (unique codes, valid zones, known airports).
A monthly GitHub Action rebuilds it and opens a pull request when something changed.

## Deployment

The site is deployed to GitHub Pages by `.github/workflows/deploy-pages.yml` on every
push to `main`. One-time setup in the repository: **Settings → Pages → Build and
deployment → Source: GitHub Actions**.
